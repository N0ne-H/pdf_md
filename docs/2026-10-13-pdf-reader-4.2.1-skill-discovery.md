官方文档将 `$HOME/.agents/skills` 列为用户级目录；隐式匹配依赖 description。文档也说明可以通过 `skills.config` 禁用 Skill，并要求修改 config.toml 后重启 Codex。[官方 Build skills 文档](https://learn.chatgpt.com/docs/build-skills)

- B 的第三章会话自行采用项目内缓存，未遵循统一用户缓存位置。
- A 的核心贡献会话做了 outline 和 search，没有逐章 read；其触发通过，不据此认证全文总结覆盖。
- 这批测试不是选择概率估计，也没有测扫描 PDF、任意跨语言查询或跨模型稳定性。

这些问题未通过修改 Core 或 BM25处理。它们属于运行权限或 Skill 执行遵循，后续可另行验收。

## 使用与重新加载建议

可靠调用方式：

```text
用 $pdf-reader 阅读 D:\路径\paper.pdf，并解释第三章。
用 $pdf-reader 找到 D:\路径\paper.pdf 中 Table 2 的实验结果。
```

在技能选择器中选中 `$pdf-reader`，比只在文字里写一个名称更容易确认调用对象。若选择器仍无该项：确认对应 config 条目为 `enabled = true`，完全退出并重新打开 Codex 客户端，然后创建新聊天再检查选择器。CLI/IDE 可用 `/skills` 或输入 `$` 检查。新会话中应能观察到读取该 `SKILL.md`，以及绝对 Conda Python 路径运行 `-m pdf_reader`；只有回答正确不算触发成功。

配置修改后按官方文档重启是正式的重新加载步骤。本次在未强制重启的情况下，新聊天与当前会话更新的技能目录均已识别到启用后的 Skill，因此没有为验收中断现有客户端。

日常本地阅读可以自然语言提问；需要确定使用缓存检索、节省文本输入或核对公式/表格时，继续显式用 `$pdf-reader`。可在请求中加“使用统一用户缓存；公式和可疑表格实际查看原页，无法查看时说明”。自动选择机制仍可能在重叠场景采用通用 PDF Skill。
