# PDF Reader 4.3：全文阅读与总结覆盖率测试报告

日期：2026-10-14。结论：本阶段实现、安装和回归已完成；全量 **39 项 pytest 通过**。停在 4.3，未进入 4.4。

## 1. 最小设计与实现

复用现有 `outline`、Chunk 和解析缓存，仅新增阅读计划及独立事件记录。规划接口只返回元数据，正文通过分批读取返回。具体问题仍可直接使用原 `search` 流程。

| 模式 | 默认内容选择 | 完成后的含义 |
|---|---|---|
| Quick | 摘要、贡献/引言、关键结果和结论；无论文式标题的手册抽样主要章节，初始最多 10 块 | 完成概览计划，通常仍有大量未读内容 |
| Standard | 默认总结模式；正文各小节的代表性内容、末尾内容及公式/表格/图片候选 | 主要章节有覆盖，允许部分章节仍为抽样 |
| Deep | 分批读取正文、补充内容和附录；初始排除参考文献及显式目录表 | 完成计划不等于整份 PDF 完整覆盖，排除项仍列为未读 |

计划采用标题、结构和候选资源的轻量规则，无论文名称或页码硬编码。实际读取可以按需求增加 `search`/`read`，不以提高百分比为目的读取无关内容。

新增 `reading.py`，CLI 增加 `chunks`、`reading-start`、`reading-next`、`reading-status`、`reading-gap`、`reading-visual`；既有 `search/read/render-page` 可附带 `--reading-record`。CLI 成功输出后记录事件，输出失败不会提交阅读进度。

阅读记录含文档 ID、模式、计划及已返回完整内容的块 ID、原 PDF 总页数、覆盖页码、章节状态、候选资源的查看回执、未读/截断/其他遗漏及事件。默认写入任务目录 `.pdf_reader_readings`，也可显式指定文件；它是任务日志，PDF 缓存仍固定在 `C:\Users\26214\.cache\pdf-reader`。原 `document.json` 和缓存版本不变。

覆盖口径：

- 搜索命中仅表示定位；完整 `read` 或完整批次片段才计入已读。重复读取不重复计数，截断片段留待完整读取。
- `covered_pages` 表示该页至少有一个完整返回的块；`fully_covered_pages` 表示该页所有已提取块均完整返回。两者都不代表页面图像已查看。
- 章节状态包含下级章节，层级间可能重叠，不能相加作为互斥章节覆盖率。
- `plan_complete` 与 `complete_text_delivery` 分开。后者还要求全部缓存块返回且没有无提取文字页；即便为真也不等于完整视觉核验。
- 图片渲染记录不产生查看状态。实际图片工具显示后才提交外部回执，状态明确为 `viewed_reported`、`external_tool_receipt_not_machine_authenticated`。
- 外层工具截断输出时，Skill 必须登记 `reading-gap` 并减小批次重读。Core 无法自动感知外层上下文截断。

## 2. CLI 与全局 Skill

所有命令继续通过原固定启动脚本。示例中的 `DOC_ID` 和记录路径替换为实际值：

```powershell
$py = 'D:\env\conda\2024\envs\pdf-md-v1\python.exe'
$reader = 'C:\Users\26214\.agents\skills\pdf-reader\scripts\reader.py'
& $py $reader outline DOC_ID
& $py $reader chunks DOC_ID --offset 0 --limit 50
& $py $reader reading-start DOC_ID --mode standard --record 'D:\大学学习\大二上\codex\output\my-reading.json'
& $py $reader reading-next 'D:\大学学习\大二上\codex\output\my-reading.json' --max-chunks 5 --max-chars 6000
& $py $reader reading-status 'D:\大学学习\大二上\codex\output\my-reading.json'
```

每批最多 20 块、20,000 正文字符；默认 5 块、6,000 字符。同一记录可跨工作目录恢复；每份记录使用一个写入者。默认状态输出精简统计，`--details` 返回完整细节；日志保留详细计算快照，不必反复发送全部元数据。

用户级 Skill 已更新：快速了解选 Quick，普通总结默认 Standard，完整阅读/深入推导选 Deep；不要求用户每次手动选模式。新增 `references/reading.md`，保留 4.2.2 的固定缓存及公式视觉规则。显式 `$pdf-reader` 仍可使用，例如“$pdf-reader 快速了解这篇论文”“$pdf-reader 总结这篇论文”“$pdf-reader 深入阅读正文和附录并解释推导”。

Core 已非 editable 重装到原 Conda 环境；项目外确认导入 `site-packages/pdf_reader`。项目目录与 `D:\TRAE10.11` 均运行固定入口，复用同一用户缓存。Skill 校验有效，`pip check` 无依赖冲突。

## 6. 已完成与限制

已完成：模式实际影响范围；分批及恢复；按成功内容输出统计块/页/章节；未读和截断披露；渲染/查看分离；全局跨项目固定缓存；两类文档三模式范围与 Token 基准；论文三模式实际总结与视觉验收；全量回归和重新安装。

仍有的限制：

1. 章节/附录/参考文献及资源候选是启发式分类，继承既有解析结果；不是全部重要公式/图表的语义清单。Deep 的 15/15 候选回执不代表所有行内公式、脚注或整份 PDF 已视觉核验。
2. Core 只能证明 CLI 完整输出过内容，不能证明模型理解了内容；无法自动探知外层截断。Skill 的 gap 处理依赖实际工具结果和模型遵循。
3. 视觉回执由调用方提供。Core 校验图片来源及页码，但不能认证宿主图片工具调用；必须结合真实工具轨迹审查，不能独立当作认证分数。
4. 空提取页按未知缺口披露；不引入 OCR 或重做解析。缓存中文本完整也不保证原 PDF 所有对象解析完整。
5. Standard/Deep 总 JSON 文本成本可能高于直接全文输入。重点收益是可控分批、可追踪进度与诚实披露，不能承诺每次节省 Token。
6. 同一日志不支持并发写入；不同阅读任务分开建记录。沙箱首次写入用户缓存仍可能需要正常授权，沿用 4.2.2 行为。
7. 本阶段没有重新做完整的自动触发概率评估；已验证实际 Skill 路径和项目外运行，沿用已验收的 4.2.1 发现机制。`$pdf-reader` 保留为可复现入口。

建议按自然语言需求自动选模式，并在答案末尾简述模式、实际块数、未读章节及关键视觉证据。精确问题继续检索；要求整份文件完整阅读时，检查日志中的排除项并按需补读，不能仅依赖 Deep 标签。下一阶段等待用户确认。
