## 2. 原有问题及定位证据

1. **Quick 的全局前10块截取挤掉方法。** 原逻辑先选择摘要/引言/结果/结论和有编号表格，再按摘要、结论、图表排序取前10块。Attention 的10块全部避开第3–5页，无法可靠支持 Transformer 核心方法概览。
2. **最长块不一定解释所属章节。** Attention 的复杂度 Table 1 沿用前页 Embeddings 标题；仅按长度，Quick 会选择表格而漏掉该节嵌入与 softmax 正文。新增复现测试后，对方法代表块增加保守的编号表格避让规则；Standard 仍保留表格。
3. **Standard 的最长/末块不能保证方法连续。** 方法中间的假设、公式解释可能落选；同一规则也会保留手册末尾重复页眉。原手册 Standard 选入9个可由章节名、文档名和页码解释的纯格式片段。
4. **任务路由表述混淆。** 旧 Skill 将“detailed analysis or derivation”列为全文 Deep 条件。局部公式的详细解释应当保持 Focused；Python 不应判断用户意图或调用新模型。
5. **Deep 缺少显式计划范围。** 默认排除参考文献/目录，旧版需要逐块补读才能完成这些部分；指定页码或章节也不能直接创建对应完整计划。

复现日志：`output/reading-4.3.2/pytest-red.txt`（9项失败），`pytest-table-red.txt`（错位表格复现失败）。修复前完整回归为 **43 passed in 59.33s**，见 `pytest-baseline.txt`。

## 4. 四种任务的新行为

|任务|新行为|边界|
|---|---|---|
|Focused|先 search，再 read 完整相关块，缺失时补作者说明、脚注或相邻证据；数学推导请求不自动扩大为全文。|不运行 reading-start；本轮只验证脚本调用与文字契约，未验证模型自主路由。|
|Quick|论文按问题/动机/贡献、方法子节、关键证据、结论/局限标题选择实质代表；手册按主要章节代表。|轻量抽样，不是全文；块数随相关结构变化，不能保证语义充分，需根据实际任务补缺。|
|Standard|方法、模型、结果、实验、讨论/局限等主要章节读完整实质块；保留正文图表公式候选，其余取实质最长和末块。|更多保留方法上下文，可能增加 Token；候选未查看不等于完成视觉核验。|

## 8. 尚未解决的阅读质量问题

1. Python 仍靠标题、结构和证据候选启发式选择，无法判断用户任务的语义是否已充分回答。新模式改善已知遗漏，不能保证未知论文的所有隐含方法、局限或实验都被选中。
2. Quick 每相关章节一个代表片段，可能漏跨块公式解释、脚注或连续推导；深层标题很多时计划也可能较大。Codex 必须按任务检查、针对性补缺，不能把固定锚点命中当作语义充分。
3. Standard 对方法/结果采取完整实质块保留，长方法论文可能接近正文全文；这是保留假设和证据的保守选择，尚未做句级语义去重。
4. 章节归属沿用已有解析器。此次仅缓解方法代表被错位编号表格替代，没有重建布局或表格，也未改变乱码/空提取/缺失数学符号的问题。
5. `--scope body` 的正文分类依赖已有 role；章节子树可能包括沿用同一标题的参考文献。完整覆盖要求可使用明确页段或 all 并披露缺口，不能默默过滤。
6. 本轮没有原页人工质量复核或真实模型试验；视觉查看机制保留，但所有新增本地运行都不能据此提交“已查看”回执。Skill 文字契约检查不等于模型行为验证。
7. 文本 Token 是离线 CLI 指标，不代表实际后端用量、缓存折扣、图片成本或账单。4.3.1既有后端累计观测另存，不在本轮推算因果收益。
8. 既有并发渲染回归尚未稳定通过，最终完整回归有1项失败，需单独定位 PNG 并发缓存读取的文件访问问题；这不影响本轮已通过的选块/Compact/范围测试，但不能承诺所有运行可靠性回归都已通过。
