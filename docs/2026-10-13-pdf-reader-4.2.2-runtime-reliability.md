## 根因调查与安全修复

### 1. 缓存漂移

4.2.1 中某会话直接重建了 `python -m pdf_reader --cache-dir 项目目录` 的命令。CLI 原有默认缓存也是项目相对路径，这属于 Core 的现有接口；只写“统一缓存”容易被执行时改写。

本次新增 `skills/pdf-reader/scripts/reader.py`，并部署为：

```text
C:\Users\26214\.agents\skills\pdf-reader\scripts\reader.py
```

固定 `CACHE_DIR`，调用已安装的 `pdf_reader.cli.main`。除了 `--cache-dir` 与 `--cache-dir=...`，也拒绝 argparse 会接受的 `--cache`、`--cache-d=...` 等缩写覆盖。启动脚本错误输出使用 UTF-8，覆盖了 GBK 终端下中文错误乱码。Skill 要求所有 CLI 命令通过该入口，不再重新拼接直连模块命令。

这对使用启动脚本的调用是确定约束；仍不能从软件层面禁止代理无视 Skill 直接另写 Core 命令。Core 原有 CLI 默认值及明确使用其他缓存的能力未修改。

### 2. 公式核验遗漏

此前公式会话读取含图片的 Markdown 后直接回答。更新的 Skill 以逐公式核验状态为依据：实际打开提取公式图片或渲染页才算视觉核验；路径、渲染成功、缓存命中、文字提取和记忆中的公式均不算查看。

无法查看时必须说明：

```text
该公式未完成视觉核验：<具体原因>
```

可继续解释可读文字。若给出未经图片确认的精确表达，必须标为未核验；只看过部分公式时分别说明已核验与未核验的范围。

### 3. PNG Permission denied

对安装旧版执行原第 5 页 `render-page`，在当前限制写入范围的沙箱中重现了相同的底层错误：

```text
pymupdf.mupdf.FzErrorSystem:
cannot open file .../rendered_pages/page-0005-<uuid>.tmp.png: Permission denied
```

检查发现：
- 用户缓存根目录与 `rendered_pages` ACL 包含用户 FullControl 和 CodexSandboxUsers Modify。
- 目录中未发现残留 `*.tmp.png`；原实现使用唯一 UUID，不存在固定临时文件名碰撞的证据。
- 当前会话允许写入的工作区根不包含用户缓存。获准执行完全相同的命令后，第 5 页成功生成，`cache_hit: false`。
- 因此本次实际复现支持沙箱写入限制为直接原因；没有证据将历史错误归因于永久 ACL 损坏或文件占用。

旧实现调用 MuPDF 原生 `Pixmap.save(path)`，拒绝写入被包装为 `FzErrorSystem`，现有 CLI 捕获列表中的 `OSError` 无法处理它，于是打印 traceback。检查实际类继承链还确认 `FzErrorSystem`、`FzErrorFormat` 继承 `FzErrorBase / Exception`，也不属于 `RuntimeError`；缓存图片校验因此显式处理该异常类。

最小代码修复位于 `src/pdf_reader/render.py`：
- `image.tobytes("png")` 编码 PNG，由 Python `temporary.open("xb")` 独占创建文件并写入。
- 保留 UUID 临时文件名和同目录原子 `replace`。并发写同一页面不会共用临时文件。
- 全量测试另复现 Windows 并发发布时的 WinError 5：目标 PNG 已由另一个请求生成，但正在被读取，替换被拒绝。现在只在这个发布失败分支检查目标能否解码且尺寸与本次结果一致；符合条件则复用已完成的缓存，否则仍报告原错误。不进行无限重试，也不接受损坏的目标图片。
- 缓存 PNG 同样由 Python 读取字节后交给 MuPDF 解码，避免原生文件 API 的权限异常漏出 CLI；捕获实际 `FzErrorBase`，损坏图片不会被当成成功。
- 写入或发布失败转为包含目标路径、权限/占用提示及原始错误的 `OSError`，CLI 正常以非零退出。
- `finally` 清理本次临时文件，清理失败不覆盖原始写入错误。若连删除也被拒绝，不能保证该临时文件可删除；不会把这种状态报告成成功。
- 已存在的有效 PNG 仍直接命中缓存，避免不必要写入。

真实沙箱拒绝测试在修复后得到一行可理解错误，无 traceback。授权执行安装版启动脚本渲染 p5、scale=1.123 后成功；从另一 cwd 重复执行返回 `cache_hit: true`。新 PNG 为 688×890，主代理实际打开查看，页面内容正确；用户渲染目录没有残留临时 PNG。

安全处理方式是保留路径、通过环境正常授权机制允许该写入并重试同一命令。没有修改 ACL、禁用沙箱、切换项目缓存或反复重试。权限不可用时可读取已有公式图；如仍不可查看，必须披露未核验。

官方配置支持 workspace-write 模式添加额外 `sandbox_workspace_write.writable_roots`。[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 若采用长期目录授权，应仅授权这个缓存目录；本次未扩大当前受管理会话的写入根，不能保证未来所有新 PNG 都无需授权。
